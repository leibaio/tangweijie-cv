项目背景Context

天天爱掼蛋的运营配置中台，覆盖渠道、活动、比赛、充值、弹窗、白名单、财务结算与 AI 数据分析。前端运营台、Java 配置服务、AI BFF 与多条下发链路共同支撑日活 40 万+ 的游戏运营。 The operations platform behind Guandan: channels, events, tournaments, recharge, popups, allowlists, finance and AI analytics. A Vue console, Java config service, AI BFF and multi-channel delivery pipelines support a 400K+ DAU game.

关键设计Key decisions

  • 一次发布写四个落点：MySQL 状态、Redis pub/sub、OSS 版本文件、游戏服版本行，分别被游戏服和客户端消费。One publish writes four targets: MySQL state, Redis pub/sub, OSS version file and game-server version row, consumed by game servers and clients.
  • 写路径按渠道并发 + 限流；读路径走 Redis 热更新，避免重启和全量刷新。Writes fan out per channel with concurrency limits; reads hot-reload through Redis, avoiding restarts and full refreshes.
  • AI BFF 不直连数据库，只编排 Java 接口、数仓 SQL 与大模型调用，保持前后端解耦。The AI BFF holds no database; it orchestrates Java APIs, warehouse SQL and LLM calls to keep the frontend and backend decoupled.

我做了什么What I built

  • 多渠道配置发布：责任链 + Redis Pub/Sub 热更新，OSS 版本文件与 game-backend 版本行；单条发布 30~60s → 1~3s（OSS 建连 100 次 → 2 次、消除 20 次冗余读取、渠道级并发限流 10）。Multi-channel config publishing: chain of responsibility + Redis pub/sub hot updates, OSS version files and game-backend version rows; single publish 30–60s → 1–3s (OSS connections 100 → 2, 20 redundant reads removed, per-channel concurrency capped at 10).
  • RBAC 动态权限：菜单 / 按钮 / API 三级控制，Shiro + Redis 分布式会话支持水平扩展。RBAC with menu, button and API-level control; Shiro + Redis distributed sessions for horizontal scaling.
  • AI BFF：Node.js + Hono + SSE，按 OpenAI 兼容协议接入 Kimi / NVIDIA NIM / DeepSeek，环境变量零代码切换；分层 Prompt 支撑自动归因、多轮追问和划选批注。AI BFF: Node.js + Hono + SSE, OpenAI-compatible access to Kimi / NVIDIA NIM / DeepSeek with zero-code provider switching; layered prompts power automated analysis, multi-turn Q&A and text-selection annotations.
  • 财务结算与审计：CPS 多渠道分成（安卓 / iOS 分开统计）、自定义 @Log AOP 记录 9 类财务操作、EasyExcel 批量导入导出。Finance settlement and audit: CPS multi-channel revenue splits (Android / iOS separated), a custom @Log AOP recording 9 financial operations, EasyExcel batch import/export.
  • MongoDB 配置对比：多环境可视化 diff，百万级牌库用 ObjectId 时间戳插值取中间样本（$gte 走 O(log N) 替代 skip 的 O(N)）。MongoDB config compare: multi-environment visual diff; million-row poker tables sampled by ObjectId timestamp interpolation ($gte O(log N) instead of skip O(N)).
  • 工程化：CompletableFuture 并发处理多渠道 OSS 上传、分批处理解决大批量发布 OOM、AOP 统一版本管理。Engineering: CompletableFuture-based concurrent OSS uploads, batch processing to prevent OOM on large publishes, AOP-based version management.
